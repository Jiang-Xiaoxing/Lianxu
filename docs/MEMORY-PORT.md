# 记忆模块实现与验证边界

全局记忆规则提供主动回查、当场写记忆两个独立开关，默认均关闭。关闭的功能不发送工具定义；工具执行与最终写入校验冻结的规则版本及权限。只有首个工具请求被服务明确拒绝为不支持工具时，最多以无工具请求重试一次；认证、限额、网络、格式及未启用工具错误均不触发回退，不自动更改开关。带工具调用的响应保留可见文本。

来源变更沿用原有按整个轮次证据计算的受影响集合，整体保留文字或整体作废。两者均使旧证据与候选失效，保留文字不恢复来源。作废只逻辑撤回非人工、非锁定记忆；人工与锁定项继续保留及复核。无受影响记忆或候选时直接保存原话，不显示影响确认。

## 重复证据、纠正与对话使用

批次操作编号及内容摘要继续提供重试幂等。自动整理与当场写入还按角色、来源轮次版本及消息侧识别同一来源；同一来源中重复引用不同片段不算独立支持。同源且正文与事实字段一致的重复写入沿用现有记录和版本，不因换编号、主题词或重复核心建议而新增副本。主题与核心不是事实身份；同一句的不同事实、不同主体、日期或生命周期仍分别处理。独立来源可通过更新已有记忆追加证据。

基础去重只进行保守的结构与正文比较，不把不同措辞或分类推断为同一事实。未配置向量或可选语义复核失败时继续使用这一路径；可选批量复核见下节。模型仍被要求优先使用已有编号。当前数据结构没有支持次数或重要性累计字段，没有新增此类计分。

每次接受新整理操作前，校验输入记忆和本批已保存结果的当前版本；外部纠正后拒绝迟到的新写入。相同操作的回执重放不重写内容，已有的人工“保留当前版本”仍可在来源有效时完成回执；新请求刷新版本，不能靠确认跳过来源校验。重试向模型提供已保存操作的id、op和target，保留已占用的新增目标别名，不再附历史操作正文；已有记忆上下文只带当前内容，历史证据快照仍留在数据库，不作为第二份当前事实注入。

模型的M编号只由实际提供的记忆集合决定，请求与响应解码共用同一集合。未展示的本批结果以独立的`resultVersions`校验，不混入编号表；旧批次缺少该字段时按空映射读取。准备批次时核对选中版本，每次尝试前重新读取并校验同一组当前内容，避免选取到准备之间的竞态及重试复用旧正文。备份重映射也处理此版本引用，不恢复在途任务。

向量缓存仍由记忆版本、内容指纹和模型身份校验，晚到结果不覆盖已纠正内容；历史引用只保存ID并重新读取当前可用记录，关联继续按端点版本与来源校验。没有另建摘要缓存或依赖系统，不删除原话、历史或无关关联，也没有改动召回算法和分数。

聊天提示固定要求只在相关时自然使用记忆，不逐条背诵或反复以“我记得”开头；明确询问过去、来源时据本次可用记录说明，缺少依据就承认。候选与历史观察不冒充当前事实，记忆不授权编造真实经历。时间、内部提示尾块和工具权限顺序保持。

显式 `date_type=birthday` 连通工具、批处理、存储与人工编辑，年度月日使用 `annualMonthDay=MM-DD`。无出生年份时 `eventDate=null`，2月29日按年度月日保留，不平移、不猜年份；已知年份按真实日历验证。不批量重解释旧记录，不增加提醒。普通正文编辑保留原日期。

回查额度默认3轮、总4000 Token、单次1500，可在原设置修改；轮数1–100，总额256–64000，单次128至总额，均为整数。自动相关召回仍默认15条，核心独立；40/20轮、有证据的2跳/评分后8入口、百分制、未知日期空及失败事务保护保持。

## 总结期间的手动修改保护（2026-10-27）

总结记忆开始前取得当前角色的进程内任务所有权。该角色的手动新增、编辑/撤回、锁定、核心选择、历史恢复、候选处理、批次人工核对和原话变更均在仓储事务内检查；覆盖导入和删除角色也检查同一保护。新增导入及其他角色不受影响。总结本身与已获授权的当场写记忆仍按原有来源、版本及任务令牌规则提交，不把人工保护扩展成全局数据库锁。

单次网络请求仍为90秒、最多3次尝试并沿用原退避。整次总结（包括等待、重试及连续批次）上限5分钟；到期或主动停止先撤销写入令牌，再恢复人工修改。独立超时任务与修改入口的到期检查共同避免不响应取消的请求长期占用保护。任务身份比较防止旧任务退出时解除新任务的保护；保护不落盘，进程重启不会残留永久锁。完整批次才移出近期原话，未完成批次的原话与已保存条目保留。

界面沿用现有样式，停用持久化修改按钮，保留查看、取消和未保存草稿；相关文案统一为“总结记忆”。本轮本地634项JVM测试通过（新增7项），应用和测试APK构建、lint通过（0错误，4项既有提示）。新增7项合成数据库/任务测试及1项界面测试已编译；ADB无在线设备，未运行这些设备测试，也未调用真实模型。

## 可选批量语义复核

复用全局“记忆向量”配置和当前总结模型，不增加角色级模型或开关。未配置向量时，逐操作校验及保存流程保持；配置后，先试算现有操作校验和精确去重（试算写入通过保存点回滚），再对新结果与同角色当前有效记忆统一生成/复用一池向量。本批新—旧、新—新使用同一池文档向量，不另生成查询向量。缓存仍按模型身份、记忆版本和内容指纹校验；提交后复用已生成向量，不把旧正文缓存附回当前事实。

相似度0.90只用于筛出待判断配对，不直接合并。可疑组内补问直接端点配对，避免把A像B、B像C当成A=C；模型输出必须覆盖`new_old`和`new_new`两组所有配对，并通过批次、编号、引用片段、类型、事实字段及矛盾判断校验。没有可疑组就不额外调用总结模型。模型只判断重复、不同、补充、更正或不确定，不生成执行指令或替代正文。

明确重复才保留规范正文并合并来源；本批多个别名仍各有幂等回执。人工/锁定项的新证据、补充、更正及不确定项进入已有候选确认，不自动覆盖。多个旧目标、矛盾输出或超出安全处理能力时保守保留原结果，不随意选一条或删除历史。启用此流程后，本次操作和完整回执在同一事务发布；流中断、取消、来源/配置变化及完成失败不发布本次半批修改。此前已保存条目与原话保留。

向量与判断只在厂商已核实限制、配置容量、输出预算或传输容量需要时拆批。已核实的限制绑定官方端点与准确模型；未知兼容服务不猜厂商批次大小，拒绝时回退原总结，不重试认证错误。传输文字上限256KiB、向量响应上限16MiB；可选复核最多处理2048份文档、60秒，整次总结仍受5分钟上限。过限回退，不截断记忆或假装查全。真实误判/漏检率没有测量，也不保证总是一次请求。

限制来源（2026-10-27核对）：[OpenAI embeddings](https://developers.openai.com/api/reference/resources/embeddings/methods/create)、[百炼文本向量](https://help.aliyun.com/zh/model-studio/embedding)。其它服务没有获得足够官方限制证据时按未知服务处理。

本地验证：660项JVM测试通过，0失败/错误/跳过；新增18项纯逻辑测试。应用和测试APK构建、lint通过（0错误、4项既有提示）。10项新增合成数据库/任务测试仅编译，未在设备运行，未调用真实模型或用户密钥。手工向量的10对样本筛出6对，5对重复漏筛1对、5对不同误送审2对；这是筛选实验，不是模型准确率。另一个合成场景的新旧2对、新新1对合为1次判断，估算输入1385Token；生成上限沿用配置，不把推理模型强压为小额输出。
