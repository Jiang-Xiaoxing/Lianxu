# 当前开发架构

`AppState`协调角色、导航和处理任务；`Store`保存本机SQLite数据。每个角色有独立会话、原话、记忆、候选与关系状态，模型入口与仓储均按角色过滤。

新数据库不生成演示角色或开场；升级不按名字清理任何已有角色。聊天和通讯录共用角色列表。删除由同一预览/确认入口调用现有角色清理事务：只取消目标角色任务，清除聊天、处理记录、资源与角色专属设置；全局模型和其他角色保留。事务失败回滚，迟到的目标回复/向量结果不得写回；删除后刷新同一列表并清理已保存的聊天草稿状态。

文字聊天经 `ConversationRunner → ChatLedger → CompanionPrompt → MemoryTools → TextChatClient`。用户消息先保存；失败/取消/来源或配置变化不得提交迟到回复。工具写入随最终回复在同一事务提交，不以助手推测或旧参考作新证据。

用户自填资料与角色设定分别保存和注入聊天提示；前者包含名字、称呼、自我介绍，后者包含完整设定、说话方式及可选开场。新字段缺失时保留旧角色定义和昵称读取。完整表单尚待设计图批准，后端与验证范围见 [用户资料与角色设定](PERSONA.md)。

记忆默认保留40个完整轮次，超过后整理最早20轮。`MemoryEngine`固定批次、逐项幂等保存，完整回执及来源版本校验成功才退休近期输入；聊天原文不删除。自动相关记忆合计默认15条，核心独立；有证据的关联最多2跳、评分后8入口，评分采用百分制。向量缓存默认未配置，失败退关键词，不切换服务商。计数按文字类型估算并加25%余量及逐条开销，不是厂商tokenizer或数学上界；已知模型容量、独立整理预算和旧配置兼容见[模型预算](MODEL-TOKEN-BUDGETS.md)。

`ProcessingRepository`保存版本历史与候选；`SourceChanges`预览并确认来源变更，旧证据失效。人工/锁定内容受到保护，冲突需人工确认。关系评估有独立模型用途与事务边界，自动默认关闭，不由普通聊天等待其完成。

`MemoryEvidenceRules`只做保守的同源、相同事实比较和消息证据归并，不推断语义或新增重要性计分。整理与当场写入共用该规则；已有事实的独立来源仍可追加。整理新操作还核对输入及本批结果的版本，防止纠正后的迟到派生写回；重试回执只含编号，当前记忆视图不附历史证据正文。原始历史保留，向量指纹、引用ID重读和关联版本过滤继续生效。聊天固定提示将记忆作为相关背景自然使用，明确问到过去或来源时仍据记录说明，不隐藏不确定性。

模型配置保存不联网；发送消息和已启用处理任务才调用明确配置的服务。密钥由Android Keystore保护，不提交源码。模型或用途缺失需明确报错，不能伪造已连接状态。

主动回查与当场写记忆分别默认关闭，回查额度全局可调；来源变更按受影响集合整体确认，旧证据保持失效；显式生日年度元数据不推测出生年份。实现与验证边界见 `docs/MEMORY-PORT.md`，构建命令见README。未归入当前四分类的记录在默认“全部”中展示原文和原分类，不自动推断或改写；不存在常驻“旧版兼容”筛选或不可用的分类编辑按钮。未接入发送链的Domain旧token预算模型已删除；旧策略JSON仍能读取，废弃的recent/batch/recall字段不再成为活动配置。核心维护目标、真实回查配额、数据库升级、恋叙v1导入与关系历史回滚保留。

## 旧聊天语气参考

`RoleExamplesPolicy` 复用用户贡献的候选筛选与编号选择规则；`RoleExamplesRepository` 用角色隔离的 preferences 状态与真实回合账本实现 waiting → 20 完整轮 offered → 用户明确同意 selecting → active，失败/中断不自动重试。`RoleExamplesEngine` 只请求当前确认的聊天模型返回 2–3 个候选编号，使用原文并在事务内核对来源版本、模型选择与状态。`RoleExamplesUi` 在聊天和表达设置提供邀请、费用/发送范围说明、取消及停用入口。

近期原话达到设置上限（默认 40 轮）时，在整理原话前停用示例但保留记录；迟到结果不能重新激活。后续发送重新校验已选来源，候选排名变化本身不使原话失效。角色提示保存以事务保留示例最新状态。升级前已有角色不自动初始化示例流程，不迁移旧数据。示例沿用现有提示层，只参考语气，不作事实依据。来源记录见 `REUSE-PROVENANCE.md`。
