# 用户资料与角色设定

本次先接通数据、提示词与备份，尚未实装新的资料表单。现有昵称入口继续可用；名字、称呼、自我介绍的完整表单等待设计图批准。不能把后端通过当作用户已能在界面填写全部字段。

## 独立资料

`UserPersona` 是一份全局用户自填资料，包含名字、希望被称呼为、自我介绍；不另设用户“说话方式”，不把记忆事实冒充用户自己填写的人设。以带版本的 JSON 保存于应用私有数据库。旧昵称在缺少新资料时作为名字读取，不批量改写原有聊天或记忆。

真实聊天链 `ChatLedger → ConversationRunner → CompanionPrompt` 读取该资料，在角色定义后、角色表达方式前插入明确标记的用户资料段。用户资料不是聊天原话、来源证据或权限声明。`{{character}}` 和 `{{user}}` 只在发送副本中单次替换；后者优先使用称呼，未填则使用名字或“旅人”。资料计入上下文预算，不静默截断。请求开始后资料变化会改变上下文指纹，旧回复及随回复暂存的记忆不能提交。

## 角色字段与开场

角色新增独立的完整设定与可选开场，沿用已有表达方式、聊天示例、附加提示、内部判断提示和初始关系。新字段缺失时继续使用旧介绍和角色提示，不清空旧字段。关系评估和语气示例挑选读取同一完整设定；挑选期间设定发生变化，不采用旧结果。

可选开场只在角色没有任何消息时保存一次，标为角色消息，不创建用户消息、完整聊天轮次、记忆来源或语气示例。已有消息不被替换。首轮提示明确说明开场不是用户证据，不强制剧情、不重复发送；是否首轮根据完整历史判断，近期原话退休后不会重新激活。完整记录导入严格恢复包内消息，不额外生成开场；新增的 v1 纯角色模板可以展示其显式携带的开场。

## 备份兼容

全部备份包含用户资料；新增导入只增加角色，保留接收端用户资料；覆盖全部按包恢复。单角色包只带角色设定、表达方式、开场及原有角色资料，不包含全局用户资料。旧包没有新字段时仍能读取，旧全部备份中的昵称继续作为用户名字。没有新增数据库表或自动迁移用户历史。

## 参考与验证边界

字段区分参考 SillyTavern 的[角色设计](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)与[用户资料](https://docs.sillytavern.app/usage/core-concepts/personas/)，只实现当前已确认范围，没有照搬多资料管理器或剧情机制。

合成测试覆盖资料编码、提示词顺序与预算、宏替换、旧字段保留、真实发送链的假客户端请求、上下文变化拒绝迟到回复、一次开场、示例变更保护和备份范围。JVM 执行、Android 测试包编译、设备运行分别记录在 PR 中；未运行的设备测试和真实模型效果不能称为通过。
